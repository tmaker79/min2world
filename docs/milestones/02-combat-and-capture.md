# Milestone 02: 전투와 도시 점령

> 이 문서는 해당 마일스톤 완료 당시의 기록이다. 현재 규칙은 [게임 가이드](../game-guide.md), 전체 진행 상태는 [개발 마일스톤](README.md)을 따른다.

## 상태

완료

## 1. 목표

현재 구현된 유닛 선택, 이동 가능 범위, 이동, 턴 종료 기능에 전투와 도시 점령을 추가한다.

이번 개발이 완료되면 플레이어는 다음 흐름으로 한 판을 끝낼 수 있어야 한다.

> 플레이어 유닛을 이동해 적과 교전하고, 적 유닛을 제거한 뒤 붉은 요새를 점령해 승리한다.

AI는 아직 행동하지 않는다. 이번 단계에서는 전투·점령·승리 규칙을 순수 TypeScript로 완성하고 React UI에 연결하는 데 집중한다.

## 2. 포함 범위

- 플레이어 유닛과 상하좌우로 인접한 적 유닛 공격
- 공격 가능한 적 타일 강조
- 보병과 기병의 공격력 및 반격력 적용
- 공격자와 방어자의 체력 감소
- 체력이 0 이하가 된 유닛 제거
- 적 유닛이 없는 도시 타일로 이동하면 도시 점령
- 적 도시 점령 시 승리 판정
- 승리 화면과 새 게임 기능
- 전투, 점령, 승리 규칙의 단위 테스트
- 공격, 점령, 승리 흐름의 UI 테스트

## 3. 제외 범위

- 적 AI 행동
- 적 세력의 수동 조작
- 원거리 공격, 범위 공격, 치명타와 확률 요소
- 지형에 따른 전투 보정
- 유닛 경험치, 성장과 장수 능력
- 도시 방어력과 공성전
- 자원 정산과 유닛 생산
- 패배 판정
- 저장과 불러오기
- 전투 애니메이션과 사운드

제외 항목은 이번 목표가 완료된 뒤 별도 단계에서 구현한다.

## 4. 전투 규칙

### 유닛 능력치

| 유닛 | 최대 체력 | 공격력 | 반격력 | 이동력 |
| --- | ---: | ---: | ---: | ---: |
| 보병 | 10 | 4 | 3 | 2 |
| 기병 | 10 | 5 | 2 | 3 |

### 공격 처리

1. 행동하지 않은 플레이어 유닛만 공격할 수 있다.
2. 공격 대상은 상하좌우로 인접한 적 유닛으로 제한한다.
3. 공격자가 먼저 자신의 공격력만큼 방어자에게 피해를 준다.
4. 방어자가 살아 있으면 자신의 반격력만큼 공격자에게 피해를 준다.
5. 체력이 0 이하가 된 유닛은 즉시 게임 상태에서 제거한다.
6. 공격 후 살아 있는 공격자는 `hasActed`가 `true`가 된다.
7. 공격으로 방어자가 제거되어도 공격자는 방어자의 타일로 자동 이동하지 않는다.
8. 공격 후 선택 상태를 해제한다.
9. 전투에는 확률을 사용하지 않는다. 같은 상태와 명령은 항상 같은 결과를 만든다.

유효하지 않은 공격 명령은 원본 상태를 그대로 반환한다. 다음 경우가 이에 해당한다.

- 공격자나 방어자가 존재하지 않음
- 공격자가 선택된 유닛이 아님
- 공격자가 플레이어 세력이 아님
- 같은 세력 공격
- 대각선 또는 두 칸 이상 떨어진 대상 공격
- 이미 행동한 유닛의 공격
- 승리 후 공격

## 5. 도시 점령과 승리 규칙

- 도시는 유닛의 이동을 방해하지 않는다.
- 플레이어 유닛이 적 유닛이 없는 적 도시 타일로 이동하면 도시의 `ownerId`를 `player`로 변경한다.
- 점령은 기존 이동 규칙의 결과로 처리하며 별도 점령 버튼을 만들지 않는다.
- 모든 도시가 플레이어 소유가 되는 즉시 게임 단계를 `victory`로 변경한다.
- 승리 후 선택, 이동, 공격, 턴 종료 명령은 상태를 변경하지 않는다.
- `새 게임`을 선택하면 초기 지도, 유닛, 도시, 턴과 자원이 모두 초기값으로 돌아간다.
- 도시 점령에 따른 자원 획득은 이번 단계에서 적용하지 않는다.

## 6. 상태와 인터페이스 변경

### 타입

```ts
type GamePhase = 'playing' | 'victory'

type CombatStats = {
  attack: number
  counterAttack: number
}
```

- `GameState`에 `phase: GamePhase`를 추가한다.
- 유닛 종류별 전투 수치는 유닛 객체마다 중복 저장하지 않고 상수 테이블에서 조회한다.
- 이동력과 전투 수치를 하나의 유닛 규칙 테이블로 통합해도 되지만 UI와 규칙 코드가 동일한 값을 참조해야 한다.

### 명령

기존 `GameAction`에 다음 명령을 추가한다.

```ts
| { type: 'unitAttacked'; attackerId: string; defenderId: string }
| { type: 'gameRestarted' }
```

### selector와 규칙 함수

- 선택된 유닛이 공격할 수 있는 적 유닛 또는 위치를 계산하는 selector를 추가한다.
- 전투 결과 계산은 React에 의존하지 않는 순수 함수로 구현한다.
- 도시 점령과 승리 판정도 reducer 내부의 UI 조건문이 아니라 게임 모듈의 규칙으로 처리한다.

## 7. UI와 상호작용

- 플레이어 유닛 선택 시 이동 가능 타일은 기존 금색 계열로 표시한다.
- 공격 가능한 적 타일은 붉은 계열 테두리와 표식으로 구분한다.
- 선택된 유닛에 인접한 공격 가능한 적 유닛을 클릭하면 즉시 공격한다.
- 정보 패널에는 기존 체력과 이동력에 공격력 및 반격력을 추가한다.
- 피해를 받은 유닛은 타일의 접근 가능한 이름과 정보 표시에서 변경된 체력을 확인할 수 있어야 한다.
- 승리 시 지도 위 또는 화면 중앙에 승리 패널을 표시한다.
- 승리 패널에는 결과 문구, 완료한 턴, `새 게임` 버튼을 제공한다.
- 승리 패널이 표시된 동안 지도와 턴 종료 버튼은 조작할 수 없게 한다.
- 별도의 이미지 에셋 없이 현재 전략 보드게임 CSS 스타일을 유지한다.

## 8. 구현 순서

1. `GamePhase`, 전투 수치와 새 action 타입을 정의한다.
2. 공격 가능 대상 계산과 전투 결과 순수 함수를 작성한다.
3. reducer에 공격, 유닛 제거, 행동 완료 처리를 연결한다.
4. 기존 이동 처리에 도시 점령과 승리 판정을 연결한다.
5. 공격 가능 타일, 전투 능력치, 변경된 체력을 UI에 표시한다.
6. 승리 패널과 새 게임 기능을 구현한다.
7. 규칙, reducer, UI 테스트를 추가하고 전체 검증을 실행한다.

## 9. 테스트 시나리오

### 규칙 및 reducer

- 보병과 기병의 공격력 및 반격력이 정확히 적용된다.
- 인접한 적만 공격할 수 있고 대각선 또는 원거리 적은 공격할 수 없다.
- 같은 세력, 이미 행동한 유닛, 존재하지 않는 유닛의 공격은 거부된다.
- 방어자가 공격 피해로 제거되면 반격하지 않는다.
- 방어자가 생존하면 공격자에게 정확한 반격 피해를 준다.
- 공격자가 반격으로 제거될 수 있다.
- 공격 후 생존한 공격자는 행동 완료 상태가 된다.
- 공격으로 제거된 유닛은 점유 타일 계산에서도 사라진다.
- 적 도시로 이동하면 소유권이 플레이어에게 변경된다.
- 모든 도시를 소유하면 게임 단계가 `victory`가 된다.
- 승리 후 게임 명령은 상태를 변경하지 않는다.
- 새 게임은 매번 독립된 초기 상태를 반환한다.

### UI

- 유닛 선택 시 이동 가능 타일과 공격 가능 적 타일이 서로 다르게 표시된다.
- 공격 가능한 적 클릭 시 양쪽 체력 또는 유닛 제거 결과가 화면에 반영된다.
- 적 도시 점령 시 승리 패널이 표시된다.
- 승리 후 지도 및 턴 종료 조작이 차단된다.
- 새 게임 버튼을 누르면 턴 1과 최초 배치로 돌아간다.

## 10. 완료 조건

다음 조건을 모두 만족하면 이번 목표를 완료한 것으로 본다.

- 플레이어가 UI만 사용해 적 유닛을 공격하고 제거할 수 있다.
- 붉은 요새를 점령하면 즉시 승리 결과를 확인할 수 있다.
- 잘못된 공격과 승리 후 행동이 게임 상태를 변경하지 않는다.
- 게임 규칙이 React 없이 단위 테스트된다.
- 새 게임으로 완전히 초기화할 수 있다.
- `npm test`, `npm run lint`, `npm run build`가 모두 통과한다.
