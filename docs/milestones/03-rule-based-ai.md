# Milestone 03: 규칙 기반 AI와 턴 전환

## 상태

다음 목표

## 1. 목표

현재 구현된 플레이어 이동·전투·도시 점령 흐름에 적 세력의 자동 행동과 양쪽 세력의 턴 전환을 추가한다.

이번 개발이 완료되면 플레이어가 턴을 종료했을 때 AI가 같은 이동·전투 규칙으로 모든 적 유닛을 행동시킨 뒤 다음 플레이어 턴을 시작해야 한다.

> 플레이어 턴 종료 → AI 유닛별 판단과 행동 → AI 턴 종료 → 다음 플레이어 턴

AI의 강함보다 예측 가능성과 규칙 재사용을 우선한다. 같은 게임 상태에서는 항상 같은 행동을 선택하며, AI 판단 코드는 React와 시간 지연에 의존하지 않는 순수 TypeScript로 구현한다.

## 2. 포함 범위

- 플레이어와 AI 세력의 명시적인 턴 전환
- 현재 행동 세력에 맞춘 선택·이동·공격·점령 규칙 일반화
- 적 유닛을 지나쳐 도시로 돌진하지 못하게 하는 통제 구역 규칙
- 인접한 플레이어 유닛 우선 공격
- 공격 대상이 없으면 가장 가까운 플레이어 도시 방향으로 이동
- 도시로 가는 경로가 없으면 가장 가까운 플레이어 유닛을 향해 이동
- 행동할 수 없는 AI 유닛의 대기 처리
- 모든 AI 유닛 행동 완료 후 자동 턴 종료
- AI 행동 간 짧은 지연과 기존 전투 모션 재사용
- AI가 모든 도시를 점령했을 때 패배 판정
- 패배 결과 패널과 새 게임
- AI 판단, 턴 전환, 패배 흐름 테스트

## 3. 제외 범위

- 난이도 선택과 여러 AI 성향
- 미니맥스, 행동 트리 탐색, 머신러닝 기반 AI
- 여러 턴을 내다보는 전략과 협공
- 체력이 낮은 유닛의 후퇴 판단
- 도시 방어를 위한 주둔 판단
- 확률에 따른 행동 변화
- 지형에 따른 전투 보정
- 플레이어 유닛 전멸만으로 발생하는 패배
- 도시 자원 정산과 유닛 생산
- 저장과 불러오기
- 이동 경로 애니메이션과 사운드

AI가 플레이어 유닛을 모두 제거해도 플레이어 소유 도시가 남아 있으면 게임은 즉시 끝나지 않는다. AI가 해당 도시까지 점령했을 때 패배한다.

## 4. 턴과 라운드 규칙

`turn`은 양쪽 세력이 한 번씩 행동하는 라운드 번호로 정의한다.

```text
턴 1 · 플레이어
  └─ 턴 종료
      └─ 턴 1 · AI
          └─ AI 자동 종료
              └─ 턴 2 · 플레이어
```

- 새 게임은 `turn: 1`, `activeFactionId: 'player'`로 시작한다.
- 플레이어가 턴을 종료하면 `activeFactionId`를 `enemy`로 변경하지만 `turn`은 증가시키지 않는다.
- AI가 턴을 종료하면 `activeFactionId`를 `player`로 변경하고 `turn`을 1 증가시킨다.
- 턴을 시작한 세력의 모든 생존 유닛은 최대 이동력을 회복하고 `hasActed`를 `false`로 초기화한다.
- 턴 전환 시 선택된 유닛을 해제한다.
- 플레이어 턴에는 적 유닛을 조작할 수 없고 AI 턴에는 플레이어 입력으로 어떤 유닛도 조작할 수 없다.
- 승리 또는 패배 상태에서는 턴이 더 진행되지 않는다.
- 전투 모션이 재생 중이면 턴 전환과 다음 AI 판단을 시작하지 않는다.

## 5. AI 행동 결정 규칙

AI는 한 번에 하나의 `GameAction`만 결정한다. reducer가 해당 action을 적용한 최신 상태를 받은 뒤 다음 action을 다시 계산한다.

### 5.1 행동할 유닛 선택

- `enemy` 세력의 생존 유닛 중 `hasActed`가 `false`인 유닛만 후보로 삼는다.
- 현재 선택된 AI 유닛이 행동 가능하면 그 유닛의 행동을 계속한다.
- 선택된 AI 유닛이 없으면 후보를 ID 오름차순으로 정렬한 뒤 첫 유닛을 선택한다.
- 배열의 현재 저장 순서에 기대지 않아 유닛 제거 후에도 행동 순서가 달라지지 않게 한다.

### 5.2 공격 우선순위

선택된 AI 유닛이 공격할 수 있는 플레이어 유닛이 있으면 이동보다 공격을 우선한다.

1. 현재 체력이 가장 낮은 대상
2. 체력이 같으면 ID 오름차순 대상

공격은 기존 `getAttackableUnits`, `resolveCombat`, `unitAttacked` 흐름을 그대로 사용한다. 공격 후 살아 있는 공격자는 행동을 마치며 다음 AI 유닛으로 넘어간다.

### 5.3 이동 목표와 경로

공격할 수 있는 대상이 없으면 다음 순서로 이동 목표를 정한다.

1. AI 유닛에서 가중 경로 비용이 가장 낮은 플레이어 소유 도시
2. 도달 가능한 플레이어 도시 경로가 없으면 가장 가까운 생존 플레이어 유닛
3. 비용이 같으면 목표 ID 오름차순

경로 계산은 기존 지도 규칙을 따른다.

- 평지 비용 1, 산 비용 2, 물 통행 불가
- 상하좌우 이동만 허용
- 다른 유닛이 있는 타일은 통과하거나 도착할 수 없음
- 적 유닛의 상하좌우 인접 타일은 통제 구역으로 취급
- 통제 구역에는 진입할 수 있지만 해당 타일을 지나서 계속 이동할 수 없음
- 남은 이동력을 가지고 통제 구역에 진입하면 이동력은 0이 되지만 인접한 적 공격은 가능
- 통제 구역 도착까지 이동력을 모두 사용했다면 일반 이동 완료와 같이 공격 불가
- 턴 시작부터 통제 구역에 있던 유닛은 공격하거나 구역 밖으로 이동 가능
- 목표 도시에 플레이어 유닛이 있으면 목표 타일까지의 경로는 평가할 수 있지만 실제 이동은 인접한 빈 타일까지만 허용
- 맨해튼 거리만 사용하지 않고 물과 산을 반영한 가중 최단 경로를 사용

현재 남은 이동력으로 갈 수 있는 빈 타일 중 목표까지 남은 경로 비용이 가장 낮은 타일을 선택한다. 후보가 같으면 다음 순서로 결정한다.

1. 이번 이동에서 더 많은 이동력을 소비하는 타일
2. `y`가 작은 타일
3. `x`가 작은 타일

이동 후에도 이동력이 남아 있으면 최신 상태에서 공격 여부와 다음 이동을 다시 판단한다. 각 이동은 반드시 1 이상의 이동력을 소비하므로 같은 상태를 반복하는 무한 루프가 발생하지 않아야 한다.

### 5.4 대기와 AI 턴 종료

- 공격할 수 없고 목표에 더 가까워지는 유효한 이동도 없으면 해당 유닛은 `unitWaited`로 행동을 마친다.
- 모든 AI 유닛이 행동을 마쳤거나 생존한 AI 유닛이 없으면 `turnEnded`를 반환한다.
- AI 판단에는 난수, 현재 시간과 브라우저 API를 사용하지 않는다.
- 동일한 `GameState`를 입력하면 항상 동일한 action을 반환한다.
- 판단 함수는 입력 상태를 변경하지 않는다.

## 6. 도시 점령과 게임 종료

- 도시 점령은 플레이어와 AI 모두 동일한 `captureCityAt` 규칙을 사용한다.
- 플레이어가 모든 도시를 소유하면 기존처럼 `victory`가 된다.
- AI가 모든 도시를 소유하면 즉시 `defeat`가 된다.
- 마지막 도시 점령으로 결과가 결정되면 진행 중인 AI 실행 예약을 취소하고 추가 action을 전달하지 않는다.
- 승리와 패배 상태에서는 `gameRestarted`를 제외한 모든 게임 action이 원본 상태를 반환한다.
- 새 게임은 턴, 현재 세력, 유닛, 체력, 도시 소유권과 결과 상태를 모두 초기화한다.

## 7. 상태와 인터페이스 변경

### 타입

```ts
type GamePhase = 'playing' | 'victory' | 'defeat'

type AiDecision = GameAction | undefined
```

- 상태 구조 변경을 반영해 `schemaVersion`을 `4`로 올린다.
- `activeFactionId`를 선택, 이동, 공격, 점령과 턴 초기화의 공통 기준으로 사용한다.
- 플레이어 전용으로 고정된 reducer 조건과 승리 판정을 현재 행동 세력 기준으로 일반화한다.
- 통제 구역 진입 후 공격을 허용하기 위해 `movementRemaining: 0`과 `hasActed: false`의 조합을 `공격만 가능` 상태로 사용한다.

### 명령

기존 `GameAction`에 다음 명령을 추가한다.

```ts
| { type: 'unitWaited'; unitId: string }
```

`unitWaited`는 현재 행동 세력의 선택된 미행동 유닛만 대상으로 한다. 유효한 대기는 `movementRemaining`을 0으로, `hasActed`를 `true`로 변경하고 선택을 해제한다. 잘못된 명령은 원본 상태를 반환한다.

### 순수 AI 인터페이스

```ts
function chooseAiAction(state: GameState): GameAction | undefined
```

- AI 턴이 아니거나 게임이 종료되었으면 `undefined`를 반환한다.
- 실행할 행동이 있으면 기존 게임 action 하나를 반환한다.
- 타이머를 만들거나 reducer를 직접 호출하지 않는다.
- 경로와 후보 점수 계산은 별도의 작은 순수 함수로 분리해 단위 테스트한다.

## 8. 코드 구조와 책임

```text
src/
├─ game/
│  ├─ ai.ts              # 목표, 경로, 다음 action 결정
│  ├─ rules.ts           # 양쪽 세력이 공유하는 이동·전투·점령 규칙
│  ├─ reducer.ts         # action 검증과 상태 전이
│  └─ selectors.ts       # 현재 세력의 파생 상태
├─ hooks/
│  └─ useAiTurn.ts       # AI action 실행 간격과 중단 처리
└─ components/
   └─ GameResultPanel.tsx # 승리·패배 공통 결과 UI
```

- `game/ai.ts`는 React, DOM, 타이머를 import하지 않는다.
- `useAiTurn`은 AI 판단 결과를 일정 간격으로 하나씩 dispatch한다.
- 전투 action은 플레이어 클릭과 AI가 같은 전투 모션 시작 함수를 사용한다.
- 전투 결과가 reducer에 반영되고 모션이 끝난 뒤에만 다음 AI 판단을 실행한다.
- 훅이 다시 실행되거나 컴포넌트가 해제될 때 예약된 타이머를 정리한다.
- 개발 환경의 React Strict Mode에서도 AI action이 중복 실행되지 않아야 한다.

## 9. UI와 상호작용

- 상단 상태바에 `플레이어 턴` 또는 `AI 턴`을 표시한다.
- AI 턴에는 턴 종료 버튼을 비활성화하고 `AI 작전 중…` 상태를 보여 준다.
- AI가 선택한 유닛에는 기존 선택 테두리를 표시해 현재 행동 주체를 알 수 있게 한다.
- AI 이동과 공격 사이에 짧은 간격을 두어 행동 흐름을 눈으로 따라갈 수 있게 한다.
- AI 공격에도 기존 돌진, 피격, 피해 숫자, 반격과 사망 모션을 재사용한다.
- AI 턴 동안 지도 클릭과 Enter 턴 종료 입력을 차단한다.
- `prefers-reduced-motion` 환경에서는 기존처럼 전투 모션과 행동 간격을 짧게 줄인다.
- 패배 시 완료 라운드와 `새 게임` 버튼이 있는 결과 패널을 표시한다.
- 승리와 패배 패널은 공통 컴포넌트로 정리하고 결과에 따라 문구와 색상만 변경한다.
- 상태 변화는 스크린 리더가 알 수 있도록 현재 세력과 AI 행동 결과를 `status` 영역에 알린다.

AI 행동 기본 간격은 약 350~500ms로 두되 테스트에서는 가짜 타이머로 제어한다. 지연 시간은 게임 규칙이 아니라 UI 상수로 관리한다.

## 10. 구현 순서

1. `GamePhase`, `schemaVersion`, `unitWaited` 타입과 reducer 처리를 추가한다.
2. 턴 종료와 유닛 초기화를 현재 세력 기준의 공통 규칙으로 변경한다.
3. AI의 도시 점령과 패배 판정을 연결한다.
4. 가중 경로 비용과 이동 후보 평가 함수를 구현한다.
5. `chooseAiAction`에 선택, 공격, 이동, 대기, 턴 종료 우선순위를 구현한다.
6. AI action을 순차 실행하는 React 훅을 만들고 기존 전투 모션과 연결한다.
7. 상태바, 입력 차단과 승리·패배 공통 결과 패널을 구현한다.
8. 규칙, reducer, AI와 UI 테스트를 추가하고 전체 검증을 실행한다.

## 11. 테스트 시나리오

### AI 판단

- 인접한 플레이어 유닛이 있으면 이동하지 않고 공격한다.
- 공격 대상이 여러 개면 체력이 가장 낮은 대상, 그다음 ID 순서로 선택한다.
- 공격 대상이 없으면 가장 가까운 플레이어 도시 방향으로 이동한다.
- 물을 가로지르지 않고 통로를 사용하며 산의 이동 비용을 반영한다.
- 적 통제 구역에는 진입할 수 있지만 이를 관통해 도시로 이동하지 않는다.
- 다른 유닛이 점유한 타일을 통과하거나 도착지로 선택하지 않는다.
- 도시로 가는 경로가 없으면 가장 가까운 플레이어 유닛을 목표로 삼는다.
- 이동 후 적과 인접하고 이동력이 남아 있으면 다시 판단해 공격한다.
- 이동하거나 공격할 수 없는 유닛은 대기한다.
- 행동 가능한 AI 유닛이 없으면 턴을 종료한다.
- 같은 상태에서 항상 같은 action을 반환하고 원본 상태를 변경하지 않는다.

### reducer와 턴 전환

- 플레이어 턴 종료 후 라운드 번호를 유지한 채 AI 턴이 시작된다.
- AI 턴 종료 후 라운드 번호가 증가하고 플레이어 턴이 시작된다.
- 새로 턴을 시작한 세력의 유닛만 이동력과 행동 상태가 초기화된다.
- 현재 세력이 아닌 유닛의 선택, 이동, 공격과 대기는 거부된다.
- AI도 플레이어와 같은 지형 비용, 점유, 전투와 도시 점령 규칙을 따른다.
- AI가 모든 도시를 소유하면 `defeat`가 된다.
- 승리 또는 패배 뒤 모든 action이 차단되고 새 게임만 허용된다.

### UI 통합

- 플레이어가 버튼이나 Enter로 턴을 종료하면 AI 턴 표시로 바뀐다.
- AI 턴 동안 지도와 턴 종료 입력이 차단된다.
- 가짜 타이머를 진행하면 AI의 선택, 이동과 공격이 정해진 순서로 보인다.
- AI 전투 중 기존 전투 모션과 중복 입력 차단이 적용된다.
- 모든 AI 유닛의 행동 후 자동으로 다음 플레이어 턴이 시작된다.
- AI가 마지막 도시를 점령하면 패배 패널이 표시되고 예약된 행동이 중단된다.
- 새 게임을 누르면 턴 1 플레이어 상태와 최초 배치로 돌아간다.

기존 이동·전투·승리 테스트를 유지하고 최종적으로 다음 검증을 모두 통과시킨다.

```bash
npm test
npm run lint
npm run build
git diff --check
```

## 12. 완료 조건

다음 조건을 모두 만족하면 이번 목표를 완료한 것으로 본다.

- 플레이어가 턴을 종료하면 별도 입력 없이 AI가 모든 유닛을 행동시킨다.
- AI가 유효하지 않은 이동이나 공격을 하지 않는다.
- AI의 선택 결과가 결정론적이며 React 없이 단위 테스트된다.
- 플레이어와 AI가 동일한 이동·전투·점령 규칙을 사용한다.
- AI 행동과 전투 모션을 화면에서 확인할 수 있고 실행 중 입력이 안전하게 차단된다.
- AI 턴이 끝나면 라운드가 증가하고 플레이어 유닛이 다시 행동할 수 있다.
- AI가 모든 도시를 점령하면 패배하고 새 게임을 시작할 수 있다.
- 기존 테스트를 포함해 `npm test`, `npm run lint`, `npm run build`, `git diff --check`가 모두 통과한다.
